# Анализатор продаж компаний (Мосбиржа и мировые рынки)

Веб-приложение на **Python и Streamlit**. По тикеру показывает динамику выручки, прибыльность, мультипликаторы, дивиденды
и цену акции, считает рост, CAGR, маржу, ROE, волатильность и просадку, сравнивает до 6 компаний на одном экране,
пересчитывает значения из долларов в рубли и с поправкой на инфляцию, выгружает данные в CSV и Excel и проверяет
качество собственного файла данных.

- **Рынок РФ (Мосбиржа):** название бумаги и цены берутся из MOEX ISS API, а финансовые показатели из файла
  `financials_ru.csv`, который вы обновляете сами (автоматического бесплатного источника отчётности РФ нет).
- **Зарубежные компании:** отчётность, профиль, дивиденды и цены берутся из Yahoo Finance (`yfinance`) по одному тикеру.
- **Справочная аналитика, не инвестиционная рекомендация.** Данные по РФ собраны из новостей и пресс-релизов, а не из первичных отчётов (см. раздел 11).

## 1. Быстрый старт

**Требования:** Python 3.9 или новее и доступ в интернет (для Мосбиржи и Yahoo Finance).

| Библиотека | Для чего | Команда |
|---|---|---|
| `streamlit` | Веб-интерфейс | `pip install streamlit` |
| `pandas` | Таблицы и расчёты | `pip install pandas` |
| `plotly` | Графики | `pip install plotly` |
| `requests` | Запросы к Мосбирже | `pip install requests` |
| `yfinance` | Данные по зарубежным компаниям | `pip install yfinance` |
| `openpyxl` | Выгрузка в Excel (необязательно) | `pip install openpyxl` |
| `pytest` | Тесты (необязательно) | `pip install pytest` |

Одной командой: `pip install streamlit pandas plotly requests yfinance openpyxl pytest`

**Запуск приложения** (из папки проекта, где лежит `streamlit_app.py`):

```bash
streamlit run streamlit_app.py
```

Браузер откроется на `http://localhost:8501`. Остановить: `Ctrl+C` в консоли. Запускать через `python streamlit_app.py`
нельзя: интерфейс работает только через `streamlit run`.

**Запуск тестов:** `pytest` (из папки проекта). Подробности: раздел 10.

**Что должно лежать рядом:** `streamlit_app.py`, папка `salesanalyzer/`, файлы `financials_ru.csv` и `macro_ru.csv`
(файлы данных должны быть в одной папке с `streamlit_app.py`).

## 2. Что умеет приложение

Вверху страницы переключатель режима.

### Режим «Одна компания»

Выберите рынок (Россия / США и международный рынок) и введите **только тикер**: `SBER`, `GMKN`, `AAPL`.
Вкладки:

| Вкладка | Содержимое |
|---|---|
| **Выручка** | Выручка за последний год, рост к прошлому году со «светофором», CAGR, столбчатый график (опубликованные значения и расчётные оценки разными оттенками), график роста по годам, таблица роста, раскрывающаяся таблица с источниками и комментариями |
| **Прибыльность** | Чистая прибыль, EBITDA, чистая маржа, EBITDA-маржа, ROE (для банков), графики прибыли, маржи и ROE, динамика и CAGR чистой прибыли |
| **Прогноз** | Прогноз выручки, чистой прибыли или EBITDA на 1–2 года: базовое значение, диапазон, надёжность, график «факт и прогноз», таблица методов, проверка методов на прошлом |
| **Мультипликаторы и дивиденды** | Цена, капитализация, P/S, P/E, дивиденд на акцию, дивидендная доходность, payout, графики дивидендов и payout по годам |
| **Цена акции** | Период 1, 2 или 3 года; доходность, годовая доходность, волатильность, максимальная и текущая просадка, MA50 и MA200, тренд; график цены со скользящими средними, график просадки; скачивание цен в CSV |

Для российских компаний над вкладками есть переключатели **«Пересчитать из $ в ₽»** (для компаний с отчётностью в долларах, например Норникеля)
и **«Поправка на инфляцию»** с выбором года цен. Внизу страницы блок **экспорта** (CSV и Excel).

### Режим «Сравнение компаний»

От 2 до 6 компаний: российские выбираются из списка (по данным файла), зарубежные вводятся тикерами через запятую.
Можно смешивать рынки. Вкладки:

| Вкладка | Содержимое |
|---|---|
| **Выручка (индекс)** | Выручка, приведённая к 100 в выбранном базовом году (общий для всех компаний), чтобы сравнивать компании разного масштаба |
| **Рост и CAGR** | Сводная таблица (период, рост за последний год, CAGR по всему ряду и по общему периоду, наличие оценок) и график роста по годам |
| **Выручка в единицах** | Абсолютные значения, сгруппированные по единице измерения |
| **Прибыльность** | Таблица и график чистой маржи, EBITDA-маржи и ROE |
| **Прогноз** | Базовый прогноз выручки или чистой прибыли по выбранным компаниям: значение, диапазон, рост к последнему году, надёжность; график роста |
| **Мультипликаторы** | Цена, капитализация, P/S, P/E, дивиденд, дивидендная доходность, payout; график выбранного показателя |
| **Цена акции (индекс)** | Цены, приведённые к 100 на общую дату старта, и таблица метрик доходности и риска |

Переключатели пересчёта в рубли и инфляции работают и здесь (для российских компаний); зарубежные остаются в долларах.

### Режим «Контроль данных»

Проверяет файл `financials_ru.csv` (раздел 10): метрики, список проблем с номерами строк, матрица покрытия данных,
расчётные оценки, сырые данные, сведения о `macro_ru.csv`, экспорт результата проверки. В остальных режимах при ошибках
в файле вверху страницы появляется предупреждение.

## 4. Источники данных

| Источник | Что берётся | Где в коде |
|---|---|---|
| **MOEX ISS API** (`iss.moex.com`) | Полное название бумаги (`securities/{тикер}`); дневные свечи (`engines/stock/markets/shares/securities/{тикер}/candles`, постранично по 500, 3 года) | `data_sources/moex.py` |
| **Yahoo Finance** (`yfinance`) | Профиль (название, сектор, сайт, валюта), годовая отчётность (`Total Revenue`, `Net Income`, `EBITDA`), дивиденды, капитализация, число акций, дневные цены | `data_sources/yahoo.py` |
| **`financials_ru.csv`** | Выручка, чистая прибыль, EBITDA, ROE, число акций и дивиденды компаний РФ | `data_sources/csv_store.py` |
| **`macro_ru.csv`** | Средний курс доллара ЦБ за год и годовая инфляция (ИПЦ) | `data_sources/csv_store.py` |

Выручка российских компаний не загружается автоматически: публичный API Мосбиржи отдаёт в основном рыночные данные,
а доступ к его разделу корпоративной отчётности не подтвердился. Поэтому финансовые показатели хранятся в файле.

Запросы к ISS и Yahoo кэшируются на 1 час (`CACHE_TTL`), файлы данных перечитываются при каждом обновлении страницы.

### Надёжность: повторные попытки и сообщения об ошибках

Сетевые вызовы к Мосбирже и Yahoo устроены так:

- **Повторные попытки.** При временных сбоях запрос повторяется до `RETRY_ATTEMPTS` раз (по умолчанию 3) с растущей паузой 0,5 → 1 с. Для Мосбиржи повторяются обрывы
  соединения, таймауты и ответы сервера 429, 500, 502, 503, 504. Ошибки вида «не найдено» (например, 404 или несуществующий тикер Yahoo) не повторяются.
- **Понятные сообщения.** Вместо технических ошибок пользователь видит текст на русском: «Нет соединения с Мосбиржей…», «Мосбиржа не ответила за 10 с…»,
  «Yahoo Finance временно ограничил число запросов…» и т.п. Это исключение `DataSourceError`, его текст можно показывать как есть.
- **Кнопка «🔄 Повторить»** под сообщением об ошибке перезапускает загрузку (неудачные запросы в кэш не попадают).
- **Частичная работа.** Если не отвечает Мосбиржа, финансовые данные из `financials_ru.csv` всё равно показываются (недоступны только название и цены).
  Если у Yahoo не отвечает необязательная часть (дивиденды), остальные данные компании загружаются. В режиме сравнения не загрузившиеся компании перечисляются
  в блоке «Что не удалось загрузить».
- **Время ожидания.** В худшем случае (сервер не отвечает) одна загрузка занимает около `RETRY_ATTEMPTS × REQUEST_TIMEOUT` секунд (по умолчанию примерно 30 с),
  прежде чем появится сообщение об ошибке. Значения меняются в `config.py`.

## 5. Файл `financials_ru.csv`: формат и как обновлять

Кодировка UTF-8 (допускается UTF-8 с BOM из Excel), разделитель запятая, десятичный разделитель **точка**, без пробелов в числах.
Каждая строка описывает один показатель одной компании за один год.

| Колонка | Смысл |
|---|---|
| `ticker` | Тикер Мосбиржи (регистр не важен) |
| `year` | Отчётный год (для `shares` год, к которому относится число акций) |
| `indicator` | `revenue`, `net_income`, `ebitda`, `roe`, `dps`, `shares` |
| `value` | Значение (число) |
| `unit` | Единицы: `млрд ₽`, `млн ₽`, `млрд $`, `млн $`, `$`, `₽`, для ROE `%`, для `dps` `₽ на акцию`, для `shares` `млн шт.` |
| `metric` | Что именно считается показателем (например, «Операционный доход до резервов») |
| `is_estimate` | `true` для расчётных значений, `false` для опубликованных |
| `source` | Источник данных |
| `note` | Комментарий (обязателен для оценок) |

**Показатели:**

| `indicator` | Что это |
|---|---|
| `revenue` | Выручка (для банков: операционный доход до резервов) |
| `net_income` | Чистая прибыль |
| `ebitda` | EBITDA (для банков не используется) |
| `roe` | Рентабельность капитала, % (для банков) |
| `dps` | Дивиденд на акцию за финансовый год, в ₽ (в пересчёте на текущее число акций, если было дробление) |
| `shares` | Число акций, млн штук (нужно для капитализации и мультипликаторов) |

**Как добавить компанию или год.** Допишите строки в конец файла, код менять не нужно. Минимальный набор для полного анализа:
`revenue`, `net_income`, `shares`, `dps` (и `roe` для банков, `ebitda` для остальных). После правки откройте режим
**«Контроль данных»** или запустите `pytest -k data_files`: приложение подскажет строку с ошибкой.

**Частые ошибки:** запятая вместо точки или пробелы в числе (`4 089,0`), смешанные единицы у одной компании,
дубликат строки (год + показатель), расчётное значение без комментария.

## 6. Файл `macro_ru.csv`: курс ЦБ и инфляция

Колонки: `year`, `indicator`, `value`, `unit`, `source`, `note`. Показатели: `usd_rub` (средний курс доллара за год)
и `cpi` (инфляция декабрь к декабрю, %). Ряд инфляции должен быть непрерывным по годам.

| Год | Средний курс ЦБ, ₽ за $ | Инфляция (дек. к дек.), % |
|---|---|---|
| 2022 | 68,5494 | 11,94 |
| 2023 | 85,2466 | 7,42 |
| 2024 | 92,5652 | 9,52 |
| 2025 | 83,6203 | 5,59 |

Курс: простое среднее официальных курсов ЦБ за год по дням (при усреднении месячных средних получается 68,35 / 85,89 / 92,67 / 83,21).
Данные взяты из справочных сайтов и новостей. Чтобы подключить новый год, добавьте по строке для `usd_rub` и `cpi`.

## 8. Формулы и методика расчётов

**Рост к прошлому году:** `(значение_t − значение_(t−1)) / значение_(t−1) × 100`. Считается только для соседних лет и только если значения
в обоих годах положительны (при убытке или смене знака показывается «н/д»).

**CAGR:** `(последнее / первое) ^ (1 / число лет между ними) − 1`. Берётся между первым и последним годом ряда; нужны минимум два разных года
и положительные значения. Если в данных пропущен год, CAGR всё равно считается по крайним годам, и приложение предупреждает об этом.

**«Светофор»:** 🟢 рост от +5%, 🟡 от −5% до +5%, 🔴 падение больше 5%. Пороги меняются в `config.py` (`GROWTH_UP`, `GROWTH_DOWN`).

**Индекс выручки:** `значение / значение в базовом году × 100`. Базовый год выбирается из лет, по которым есть данные у всех выбранных компаний.

**Маржа:** чистая маржа = чистая прибыль / выручка × 100; EBITDA-маржа = EBITDA / выручка × 100. Для банков «выручка» это операционный доход, EBITDA не применяется.

**Пересчёт $ → ₽:** значение в долларах × средний курс ЦБ за этот год; «млн $» переводится в «млрд ₽» (делится на 1000). Курс берётся из `macro_ru.csv`.
Годовое среднее приближает пересчёт по датам операций (сверка: чистая прибыль Норникеля 2024 года в рублях совпала с данными компании, за 2023 год разница около 3%).

**Поправка на инфляцию (реальные значения):** значения приводятся к ценам выбранного года. Уровень цен в году считается как среднее геометрическое
уровней на конец предыдущего и текущего года (приближение для годовых потоков), по ИПЦ «декабрь к декабрю». Рост и CAGR после поправки становятся реальными.
К значениям в долларах российская инфляция не применяется. Маржа и ROE от пересчётов не меняются.

**Метрики цены:**

- доходность за период = `цена_конец / цена_начало − 1`; годовая доходность = то же, пересчитанное на год (считается для периода от 3 месяцев);
- волатильность (годовая) = стандартное отклонение дневной доходности × √252;
- максимальная просадка = наибольшее падение от предыдущего максимума внутри периода; текущая просадка = отставание последней цены от максимума;
- MA50 и MA200 = среднее цен закрытия за 50 и 200 торговых дней (считаются по всей загруженной истории, поэтому линии есть с начала периода);
- тренд: цена выше или ниже MA200.

**Прогноз показателей (выручка, чистая прибыль, EBITDA) на 1–2 года.** Данных мало (2–4 годовых значения), поэтому используются только простые и прозрачные методы:

- **линейный тренд**: прямая по методу наименьших квадратов по годам;
- **CAGR**: продолжение среднегодового темпа между первым и последним значением от последнего значения;
- **затухающий рост**: средний темп роста, который с каждым годом ослабевает (в первом году g·φ, во втором g·φ² и т.д., где φ = `FORECAST_DAMPING`, по умолчанию 0,7);
- методы роста (CAGR и затухающий) применяются только к рядам из положительных значений; при убытке в ряду остаётся линейный тренд.

Три сценария по каждому году: **база = медиана методов**; **низкий и высокий = разброс методов, расширенный на типичную ошибку методов на прошлом**
(ошибка умножается на √k для k-го года горизонта, расширение не больше 60% от базы). Выручка и EBITDA не опускаются ниже нуля.
**Проверка на прошлом:** каждый метод «прогнозирует» уже известные годы по более ранним данным (минимум по двум значениям); показываются ошибка в процентах по годам и средняя абсолютная ошибка.
**Надёжность:** «недостаточно данных» (меньше `FORECAST_MIN_POINTS` = 3 значений прогноз не строится), «низкая» (ровно 3 значения; средняя ошибка на прошлом больше 20%;
разброс годовых темпов больше 25 п.п.; нули или убытки в ряду; последнее значение расчётное) или «средняя». «Высокой» надёжности не бывает: данных слишком мало.
Прогноз строится по тем же данным, что и экран: если включён пересчёт в рубли или поправка на инфляцию, прогноз делается уже в рублях или в реальных ценах.

**Мультипликаторы:**

- капитализация = цена × число акций (для РФ число акций из файла, для США данные Yahoo);
- P/S = капитализация / выручка последнего отчётного года; P/E = капитализация / чистая прибыль последнего года (при убытке «н/д»);
- денежные показатели в долларах для российских компаний автоматически переводятся в рубли по среднему курсу;
- дивидендная доходность = дивиденд на акцию / текущая цена (США: выплаты за последние 12 месяцев);
- payout = дивиденды всего / чистая прибыль, где дивиденды всего = дивиденд на акцию × **текущее** число акций. Для прошлых лет это приближение.
  Контрольная сверка: дивиденды Сбербанка за 2024 год получились 786,9 млрд ₽ и payout 49,8%, как у самого банка.

Исторические мультипликаторы по ценам на конец года не считаются: дробления акций (Т-Технологии, Норникель) исказили бы прошлые цены.

## 10. Контроль качества данных и тесты

### Режим «Контроль данных»

Читает `financials_ru.csv` как сырой текст и ищет проблемы трёх уровней:

- 🔴 **Ошибки:** нет нужных колонок, пустой тикер, некорректный год, значение не число (строка игнорируется), дубликаты, разные единицы у одной компании,
  выручка или число акций ≤ 0, отрицательный дивиденд.
- 🟡 **Предупреждения:** неизвестный показатель, год вне диапазона, пропущенные годы, устаревшие данные (нет данных за прошлый год), нет источника или единиц,
  странный флаг оценки, оценка без пояснения, ROE не в процентах, чистая маржа больше 100%, нет выручки.
- 🔵 **Информация:** незнакомые единицы, короткий ряд (меньше 3 лет выручки), нет чистой прибыли, числа акций или дивидендов,
  EBITDA меньше чистой прибыли, резкие изменения год к году (выручка более 100%, EBITDA более 150%, чистая прибыль более 300%).

Результат: метрики, таблица проблем с номером строки, матрица покрытия (✓ есть, ≈ оценка, пусто нет данных), список оценок, сырые данные, сведения о `macro_ru.csv`.

### Автоматические тесты (pytest)

224 проверок в 11 файлах (папка `tests/`): расчёты (рост, CAGR, маржа, пересчёты, метрики цены, мультипликаторы), выгрузка, проверка данных на испорченных
примерах, сами файлы данных, а также надёжность (повторные попытки, ошибки Мосбиржи и Yahoo на заглушках, совместимость с Streamlit). Сеть, браузер и Streamlit не нужны (они подменяются заглушками).

```bash
pip install pytest
pytest                      # все тесты
pytest -k data_files        # только проверка файлов данных (после их обновления)
pytest -v                   # подробный вывод
```

Тесты сами находят папку с пакетом `salesanalyzer`: рядом с файлом `conftest.py`, в родительской или текущей папке, а также в их подпапках.
Вручную: переменная окружения `SALESANALYZER_ROOT` (PowerShell: `$env:SALESANALYZER_ROOT = "C:\путь\к\проекту"`).
В начале вывода pytest печатает найденный корень проекта.

Тесты проверялись на вынесенных ошибках: при намеренной порче формул или данных тесты падают. Они не проверяют реальные запросы к Мосбирже и Yahoo
и внешний вид страниц: это делается запуском самого приложения.

## 11. Ограничения и важные оговорки

- **Источники данных РФ вторичные.** Цифры в `financials_ru.csv` собраны из новостей, пресс-релизов и справочных сайтов, а не из первичных отчётов МСФО.
  Перед серьёзным использованием сверьте их с годовыми отчётами компаний или Центром раскрытия информации (e-disclosure.ru). Расчётные значения помечены `is_estimate = true`.
- **Выручка РФ обновляется вручную.** Автоматического бесплатного источника нет.
- **Определения показателей различаются** (банки и нефинансовые компании; скорректированные и опубликованные значения). Сравнивайте темпы роста и маржу осторожно, уровни только внутри схожих компаний.
- **Рост номинальный**, если не включена поправка на инфляцию. Реальные значения используют приближённый уровень цен в середине года.
- **Пересчёт в рубли по среднегодовому курсу** даёт приближение, а не точное значение по датам операций.
- **Прогноз — сценарная оценка, а не предсказание.** Он строится по 2–4 годовым значениям и не знает о смене отчётности, разовых событиях и курсе валют; у Лукойла (2 значения) он не строится, у Сбербанка прибыль после кризисного 2022 года даёт очень широкий диапазон. Надёжность выше «средней» не бывает.
- **Мультипликаторы текущие**, по последней цене и текущему числу акций. Payout и «дивиденды всего» за прошлые годы приблизительные.
- **Yahoo Finance** отдаёт обычно около 4 последних лет годовой отчётности; доступность и формат данных зависят от Yahoo.
- **Версии Streamlit.** Ширина графиков и таблиц задаётся через `ui/compat.py`: в новых версиях используется `width="stretch"`, в старых `use_container_width=True` (определяется автоматически).
- Реальные запросы к Мосбирже и Yahoo в автоматических тестах не проверяются (сбои и повторные попытки проверены на заглушках).

## 13. Как расширять приложение

- **Добавить компанию или год:** допишите строки в `financials_ru.csv` (раздел 5), проверьте файл в режиме «Контроль данных».
- **Добавить год инфляции и курса:** по строке `usd_rub` и `cpi` в `macro_ru.csv`.
- **Новый расчёт:** добавьте чистую функцию в подходящий модуль `salesanalyzer/core/`, покройте её тестом в `tests/`, затем подключите в `ui/`.
- **Новый показатель в файле данных:** добавьте его код в `INDICATOR_NAMES` и `KNOWN_INDICATORS` в `config.py` (и в `MONEY_INDICATORS`, если это деньги в одной единице с выручкой).
- **Новый источник данных:** модуль в `salesanalyzer/data_sources/`, кэшируйте запросы через `@st.cache_data(ttl=CACHE_TTL)`.
- **Новый экран:** модуль в `salesanalyzer/ui/` и подключение в `streamlit_app.py`.

## 15. Развёртывание на своём сервере

Приложение готово к запуску на собственном Linux-сервере в Docker: схема «интернет → Caddy (автоматический HTTPS и пароль) → контейнер с приложением».
Порт приложения наружу не публикуется, файлы данных подключаются из папки `data/` на сервере (только для чтения), поэтому цифры обновляются без пересборки образа.

Коротко:

```bash
cd /opt/sellanalyzer
mkdir -p data && cp financials_ru.csv macro_ru.csv data/
cp caddy/Caddyfile.example caddy/Caddyfile     # впишите домен, логин и хэш пароля
docker compose up -d --build
```

Полная инструкция (установка Docker, домен, пароль, обновление данных и кода, резервные копии, безопасность, частые проблемы): **[DEPLOY.md](DEPLOY.md)**.
Сборка и запуск контейнеров мной не выполнялись (нет Docker в среде разработки): проверены синтаксис конфигураций и работа приложения с такой раскладкой папок.
