# Развёртывание на своём сервере (Docker + Caddy)

Схема: **интернет → Caddy (HTTPS и пароль) → контейнер с приложением**. Порт приложения (8501) наружу не публикуется,
к нему можно попасть только через Caddy. Файлы данных лежат на сервере в папке `data/` и подключаются к контейнеру
только для чтения, поэтому цифры обновляются без пересборки образа.

> **Важное про проверку.** Конфигурацию (Dockerfile, compose, Caddyfile) я проверил на синтаксис и проверил, что приложение
> работает при такой раскладке папок и с переменной окружения для данных. Сборку образа и запуск контейнеров в Docker я
> выполнить не мог (в моей среде нет Docker), поэтому первый запуск на вашем сервере остаётся за вами. Раздел
> «Частые проблемы» в конце поможет при сбоях.

---

## 1. Что понадобится

| Что | Подробности |
|---|---|
| **Сервер (VPS)** | Linux (Ubuntu 22.04 или 24.04). Ориентир: 1–2 vCPU и 2 ГБ памяти; с запасом, если пользователей будет несколько одновременно |
| **Docker и Docker Compose** | Раздел 2 |
| **Домен** | Нужен для HTTPS-сертификата. A-запись домена должна указывать на IP сервера. Без домена см. раздел 8 |
| **Открытые порты** | 80 и 443 (и 22 для SSH) |
| **Доступ из сервера в интернет** | К `iss.moex.com` (Мосбиржа) и к Yahoo Finance. Проверка в разделе 9 |

## 2. Установка Docker на сервере

Подключитесь по SSH и установите Docker по официальной инструкции для вашей системы: <https://docs.docker.com/engine/install/ubuntu/>.
Быстрый способ (официальный скрипт):

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER      # затем выйдите и войдите по SSH заново
docker --version
docker compose version
```

## 3. Загрузка проекта на сервер

Папка проекта на сервере, например `/opt/sellanalyzer`. Нужны эти файлы и папки из архива проекта
(тесты, `.venv` и `README.md` на сервере не нужны):

```
Dockerfile
docker-compose.yml
requirements-prod.txt
streamlit_app.py
salesanalyzer/          (папка целиком)
.streamlit/             (папка целиком)
caddy/                  (папка целиком)
financials_ru.csv
macro_ru.csv
```

С компьютера на Windows (PowerShell, из папки проекта; `user` и `IP` замените своими):

```powershell
ssh user@IP "sudo mkdir -p /opt/sellanalyzer && sudo chown user /opt/sellanalyzer"
scp -r Dockerfile docker-compose.yml requirements-prod.txt streamlit_app.py salesanalyzer .streamlit caddy financials_ru.csv macro_ru.csv user@IP:/opt/sellanalyzer/
```

Либо загрузите проект через Git, если он у вас в репозитории (в нём не должно быть пароля: `caddy/Caddyfile` и `data/` указаны в `.gitignore`).

## 4. Папка с данными

На сервере создайте папку `data` и положите в неё два файла. Приложение читает их из этой папки:

```bash
cd /opt/sellanalyzer
mkdir -p data
cp financials_ru.csv macro_ru.csv data/
chmod -R a+rX data          # контейнер работает не от root и должен уметь читать файлы
```

## 5. Домен, пароль и файл Caddyfile

1. **DNS.** В панели домена создайте A-запись (например, `sellanalyzer.example.com`) на IP сервера. Подождите, пока запись обновится.
2. **Хэш пароля.** Выполните на сервере и введите пароль два раза. Скопируйте полученную строку (начинается с `$2a$`):

   ```bash
   docker run --rm -it caddy:2 caddy hash-password
   ```
3. **Caddyfile.**

   ```bash
   cp caddy/Caddyfile.example caddy/Caddyfile
   nano caddy/Caddyfile
   ```

   Замените домен, логин (`analyst`) и `ХЭШ_ПАРОЛЯ` на свои значения. Сертификат HTTPS Caddy получит и продлит сам.
4. **Брандмауэр** (если используете `ufw`; Docker сам публикует порты в обход `ufw`, поэтому порт приложения мы вообще не публикуем):

   ```bash
   sudo ufw allow OpenSSH
   sudo ufw allow 80/tcp
   sudo ufw allow 443/tcp
   sudo ufw enable
   ```

## 6. Запуск

```bash
cd /opt/sellanalyzer
docker compose up -d --build
docker compose ps                  # у приложения через минуту должно быть состояние «healthy»
docker compose logs -f app         # журнал приложения (выход: Ctrl+C)
```

Откройте `https://ваш-домен`, введите логин и пароль. Приложение перезапускается само после перезагрузки сервера (`restart: unless-stopped`).

## 7. Повседневная работа

**Обновить данные** (CSV): отредактируйте файлы в `data/` на сервере или загрузите новые с компьютера:

```powershell
scp financials_ru.csv macro_ru.csv user@IP:/opt/sellanalyzer/data/
```

Пересборка и перезапуск не нужны: обновите страницу в браузере. После правки откройте режим **«Контроль данных»**,
чтобы убедиться, что в файле нет ошибок. Перед загрузкой удобно проверить файлы локально командой `pytest -k data_files`.

**Обновить приложение** (новая версия кода): загрузите изменённые файлы (`salesanalyzer/`, `streamlit_app.py` и т.д.), затем:

```bash
cd /opt/sellanalyzer
docker compose up -d --build
```

Перед отправкой кода на сервер запустите `pytest` на своём компьютере.

**Обновить библиотеки** (например, `yfinance`, если Yahoo изменил формат ответов): пересоберите образ без кэша слоёв:

```bash
docker compose build --no-cache app && docker compose up -d
```

**Остановить и запустить:**

```bash
docker compose stop        # остановить
docker compose start       # запустить
docker compose down        # удалить контейнеры (данные в data/ и сертификаты сохраняются)
```

**Резервная копия.** Достаточно копировать папку `data/` и файл `caddy/Caddyfile`. Пример ежедневной копии по расписанию (`crontab -e`):

```
0 3 * * * tar czf /opt/backups/sellanalyzer-data-$(date +\%F).tgz -C /opt/sellanalyzer data caddy/Caddyfile
```

(папку `/opt/backups` нужно создать заранее). Сертификаты Caddy хранятся в томе `caddy_data` и при потере выпускаются заново автоматически.

**Место на диске.** Время от времени удаляйте старые образы: `docker image prune -f`.

## 8. Варианты без домена или без интернета

- **Только локальная сеть, без домена.** В `caddy/Caddyfile` используйте блок для IP-адреса с `tls internal` (закомментированный пример есть в `Caddyfile.example`).
  Сертификат самоподписанный: браузер покажет предупреждение, его можно подтвердить вручную.
- **Проверка контейнера на своём компьютере** (Docker Desktop для Windows), без прокси и пароля, только для `localhost`:

  ```powershell
  docker compose -f docker-compose.yml -f docker-compose.local.yml up --build app
  ```

  Откройте `http://localhost:8501`. Файлы данных берутся из папки `data/` (создайте её, как в разделе 4) или из образа по умолчанию, если папки нет.

## 9. Проверка доступа сервера к источникам данных

Приложению с сервера нужны Мосбиржа и Yahoo Finance. Быстрая проверка с самого сервера:

```bash
curl -s -o /dev/null -w "Мосбиржа: HTTP %{http_code}\n" "https://iss.moex.com/iss/securities/SBER.json"
curl -s -o /dev/null -w "Yahoo:    HTTP %{http_code}\n" "https://query1.finance.yahoo.com/"
```

Код 200 (или 3xx/4xx у Yahoo для корневой страницы) означает, что соединение есть. Таймаут или отказ значат, что сервер не видит источник
(сетевые ограничения провайдера или межсетевой экран). Yahoo часто ограничивает запросы с адресов дата-центров: в таком случае у зарубежных
компаний будут сообщения об ограничении запросов, а данные по российским компаниям из файла продолжат работать.

## 10. Безопасность

- **Доступ только по паролю и HTTPS.** Пароль общий на всех пользователей (базовая авторизация Caddy). Отдельных учётных записей у приложения нет.
  Если нужны разные пользователи, в `basic_auth` можно добавить несколько строк «логин хэш».
- **Не публикуйте порт 8501** (в `docker-compose.yml` он только `expose`, а не `ports`) и не открывайте его в брандмауэре.
- **SSH.** Входите по ключам, отключите вход по паролю, регулярно обновляйте систему (`sudo apt update && sudo apt upgrade`).
- **Файл `caddy/Caddyfile` содержит хэш пароля.** Не добавляйте его в репозиторий (он указан в `.gitignore`).
- **Данные и ответственность.** Цифры по российским компаниям собраны из новостей и пресс-релизов, а не из первичных отчётов. Если приложением будут пользоваться
  другие люди, сверьте данные с отчётами и оставьте дисклеймер: это справочная аналитика, а не инвестиционная рекомендация.

## 11. Частые проблемы

| Симптом | Причина и что делать |
|---|---|
| Браузер пишет «502 Bad Gateway» | Приложение ещё запускается или упало. `docker compose ps` и `docker compose logs app`; подождите, пока состояние станет «healthy» |
| Сертификат не выдаётся, браузер предупреждает о небезопасном соединении | A-запись домена ещё не указывает на сервер, закрыты порты 80/443 или домен в `Caddyfile` написан неверно. Смотрите `docker compose logs caddy` |
| Страница после ввода пароля «загружается» бесконечно | Попробуйте другой браузер или режим инкогнито. Проверьте, что Caddy проксирует именно на `app:8501` |
| В приложении: «Файл financials_ru.csv не найден» | Папка `data/` пуста или не примонтирована. Проверьте раздел 4 и права: `chmod -R a+rX data` |
| В `docker compose ps` у приложения «unhealthy» | Смотрите `docker compose logs app`: чаще всего ошибка установки библиотек или данных |
| Мосбиржа или Yahoo пишут «нет соединения» | Раздел 9: проверьте доступ с сервера. Приложение само повторяет запрос 3 раза и показывает кнопку «Повторить» |
| Yahoo: «ограничил число запросов» | Подождите минуту-две и нажмите «Повторить»; если повторяется постоянно, обновите `yfinance` (раздел 7) |
| После правки `Caddyfile` ничего не изменилось | `docker compose restart caddy` (папка `caddy/` подключена целиком, поэтому изменения видны контейнеру) |
| Не хватает памяти (контейнер перезапускается) | Увеличьте оперативную память сервера или ограничьте число одновременных пользователей |

## 12. Что находится в проекте для развёртывания

| Файл | Назначение |
|---|---|
| `Dockerfile` | Образ приложения на Python 3.12; запуск не от root; проверка работоспособности (healthcheck) |
| `docker-compose.yml` | Два контейнера: приложение и Caddy; том с данными, том с сертификатами |
| `docker-compose.local.yml` | Дополнение для локальной проверки: открывает `localhost:8501` |
| `requirements-prod.txt` | Библиотеки образа (нижние границы версий) |
| `.streamlit/config.toml` | Настройки Streamlit для сервера (без сбора статистики, без отслеживания файлов) |
| `caddy/Caddyfile.example` | Шаблон прокси: домен, логин, хэш пароля |
| `.dockerignore`, `.gitignore` | Что не попадает в образ и в репозиторий |
| Переменная `SALESANALYZER_DATA_DIR` | Папка с файлами данных; в образе равна `/data` (в `Dockerfile`) |
